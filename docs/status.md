# Status

What is left, what is known broken, and what is waiting on a decision. Read `docs/architecture.md` for the design and `docs/architecture-plan.md` for how the current shape was arrived at.

Update this file when work lands. It deliberately carries no test count and no commit hashes: both are one command away and wrong the moment anyone commits.

## Waiting on the operator

- `package.json` has no `"private": true`, and `README.md` tells the reader to `npm install -g pi-agents`, a package that is not published and is not intended to be. Either publish it or say plainly that a local checkout is the only install.

## Known defects

None of these lose work or corrupt state. Each was found by the change that reported it, and each is reproducible.

| Defect | Where | What the operator sees |
|---|---|---|
| `PROCESS_EXIT_PROOF_MS` is 2 s with no option | `cli/daemon-commands.mjs` | A daemon the kernel takes longer to reap turns a correct stop into exit code 5 `DAEMON_STILL_RUNNING`. |
| `CRASH_REPORT_TIMEOUT_MS` is 1 s | `runtime/installed-pi-worker.mjs` | Under load a crashing worker loses its own explanation, which is the one moment that explanation matters. |

| `runViewerTransition` fires `detach` without awaiting it | `app/list/standalone-list.mjs` | A fast reopen-then-delete races its own detach. The client orders a reattach behind that session's in-flight detach, so what remains is a delete racing it. |
| `migrateLegacyState` refuses any root that ever opened a viewer | `runtime/state-migration.mjs` | Pre-existing. It means that path cannot succeed on the operator's machine today. |
| The destination daemon `migrateLegacyState` starts has no spawn seam | `runtime/state-migration.mjs` | `test/migration.integration.test.mjs` cannot record it until it publishes, so a test timing out inside `runDashboardApp` still leaks one daemon. Every other real-process suite records at the spawn. |

## Two open questions that are not defects

**Test doubles that cannot fail the way production fails.** A fake `request` hid a broken `daemon stop --stop-workers` behind a fully green suite. A fake server that accepted every viewer subscription hid a viewer that froze on a real refusal. A fixture Pi that emitted a help banner where a version belonged reinforced the bug it should have caught. The pattern is a double that only models success. The fix is per-site and costs real-process test time on a machine whose load already swings between 2 and 38, so it is a judgment call rather than a sweep.

**Durable-format collapses proposed by review, none executed.** Fold `runtime.piVersion` into `runtime.capabilities.reportedVersion`; drop `registryRevision` and `runtime` from viewer snapshots. Each removes real bytes and real code. Each is also read after a crash by code that must not guess, so a collapse that makes a half-written file ambiguous is not a simplification. The viewer checkpoint log this list also named is gone: the whole durable viewer format went with item 1 below.

## Housekeeping

- Files on the operator's state root that no code names and nothing removes: everything under `index/` (`index/events.jsonl`, `index/viewer/*`) and under `queue/` (`queue/commands.jsonl`), `daemon/launch-results.json`, `cli/pending/*.json`, `daemon/attachment-results.jsonl`, `daemon/event-acks.json`, `frontend-state.json`. The `index/viewer` files joined this list when the live tail moved into the worker, and the `queue/`, launch-result and pending-request files joined it when the command journal went; all are left where they are, with no parser and no ignore branch. A state-root migration drops the last three rather than copying them forward.
- The state root is still `~/.local/state/pi-dashboard`. It is renamed to `pi-agents` in place on the first start with no live daemon and no live worker, so it stays until every session is stopped once.

## Verification already done

Gates 0 through 4 pass. Gate 0 and 1 by hand on the live daemon; 2, 3 and 4 on temporary roots with disposable sessions, evidence recorded per item.

Gate 4 was widened before it ran, because as specified it never broke a live viewer's socket nor let events accumulate past the daemon's subscriber bound, and so could not have caught the silent viewer freeze it was meant to protect against. It found the viewer file-handle leak that killed the daemon on Node 24 and later. **A gate aimed at the failure you already fixed is not a gate.**

## Adopting Claude Code's process shape

Wanted, and the reason to want it: it deletes subsystems rather than tidying them. An architecture review costed a from-scratch redesign at 24 to 35 percent smaller than the 17,691 production lines of that day (16,884 now) and said half is unreachable under our own constraints. The four changes below are the part of that reduction Claude Code's shipped design already validates, so each one is a deletion with a working precedent rather than a bet. Read `docs/reference/claude-code-behavior.md` before starting any of them.

All four are done. Item 3 shipped alone, as it had to.

**1. The live tail belongs to the worker, not the daemon. Done.** The worker keeps 262,144 bytes of the Pi frames it produced and replays them as one `pi_tail` frame on every connection after its launch; the daemon rebuilds that session's viewer state from Pi's canonical file plus that tail and tells every subscriber to resynchronize. `subscribe_viewer` now answers with the snapshot it continues, both taken under one frame lock, so nothing can fall between them; `get_viewer_snapshot` and the viewer resume cursor are gone, which is client protocol 4. The durable viewer event, checkpoint and snapshot formats went with them, along with their contracts, their recovery paths, and the normalizer's restore, checkpoint and durable-event surface. A daemon restart now keeps partial streaming text, which the durable store could never do: it was absent for exactly the frames that mattered.

The 800-to-1,500-line estimate was wrong, and the shape of the error is worth keeping. It deleted 544 production lines and added 521: the durable store was only 288 lines, and its replacement is not free — 129 lines of live stream, 74 of worker tail, and the rebuild and subscribe-seam changes inside `runtime/reconciliation.mjs`. Net 23 production lines removed, with 171 test lines added. What actually left is a durable format nothing may misread after a crash, its recovery path, and a resume protocol; count this one in concepts, not lines. Items 2 to 4 were costed the same way, so read their line estimates as upper bounds on gross deletion, not on net.

**2. Delete the daemon-wide command journal; the worker's durable inbox is the acceptance boundary. Done.** [`docs/command-acceptance.md`](command-acceptance.md) is the crash matrix that had to be settled first: no crash point loses the operator's text, and every row says whether an action can happen twice and how he recovers. The worker's replay log now carries that text, which is what makes the boundary real — before this it recorded only that a command existed, and the text lived in the journal being deleted. Gone with the journal: the daemon stage machine, `resolve_delivery` and its CLI verb, the frontend's resolution overlay, `queue/commands.jsonl`, `daemon/launch-results.json`, `cli/pending/*.json`, and the reconciliation redelivery surface. A command answer is now `{kind: "command", sessionId}`; a refusal or an unattributable outcome is one typed failure carrying `DELIVERY_UNKNOWN` or the refusal's own code. That is client protocol 5.

Measured, not estimated, across the three commits that did it: 862 production lines removed against 192 added, **net 670 production lines**, plus 284 test lines removed. That is the bottom of the 700-to-1,200 estimate on gross deletion and just below it on net, which is the closest any estimate in this release has come. Three quarters of the deletion was outside the journal itself, which was only 221 lines: 215 came out of `runtime/daemon.mjs`, whose launch, Stop, Delete and respawn paths each threaded four stage transitions through their own control flow, and 215 out of `cli/session-commands.mjs`, whose durable pending record existed only to give that journal a stable retry identity. What actually left is a durable format nothing may misread after a crash and a second place a command's fate was recorded; the guarantees the docs claimed for it were never true, and the honest ones are now written down in one file.

The documentation had called this exactly-once delivery. It never was, and no stage machine could have made it so: Pi exposes no idempotency key, so a crash after the bytes are written is genuinely ambiguous. What survives provides the operator's text durably before any Pi write, one Pi write per request identity, no silent retry of an ambiguous one, and an honest `DELIVERY_UNKNOWN`.

**3. Invert the worker socket. Done.** The daemon names each run's socket in `daemon/workers.json` before it spawns, the worker listens on it at mode 0600 under `daemon/workers/`, and the daemon connects and authenticates with the per-run token already in that file, verifying PID, process-start identity and process group exactly as before. Adoption is now a connect: the 15-second reconnect poll and the `WORKER_RECONNECT_TIMEOUT` conflict are gone, the worker's reconnect backoff ladder is gone, and the pre-spawn connection race is gone with it — the daemon knows the PID before it connects, so there is no held connection waiting for a PID to be published. The `worker` role on `control.sock` is gone; that socket now carries frontends and control clients only. Worker socket protocol is 2 and client protocol is 6.

**This one added lines, and by more than any other item here: 17,291 production lines against 16,936, net 355 added** (`runtime/worker-socket.mjs` +229, `runtime/reconciliation.mjs` +132, `runtime/test-fixtures.mjs` +57, `runtime/daemon.mjs` +30, `runtime/installed-pi-worker.mjs` +21, `shared/contracts.mjs` +4, against `runtime/daemon-connector.mjs` −106 and −12 across the supervisor and the worker), with 191 test lines added. The count is honest and the concept count is close to even: a startup deadline, a per-worker socket file with its own lifetime and cleanup, a daemon-side route reopen, and a row-level unreachable marker replace a reconnect ladder, a reconnect poll, a pre-spawn race, and a socket role. What was bought is not size. It is that adoption is deterministic rather than a wait, that a daemon replacement cannot fail because a worker was slow to find it, and that a live worker is no longer the thing that has to go looking for a daemon.

An operator upgrading across this meets his own live workers. They speak the previous arrangement and listen on nothing, and the daemon says so rather than refusing to start: the start succeeds, a `worker_unreachable` diagnostic names `WORKER_PROTOCOL_INCOMPATIBLE` and the fix, every affected row carries `workerUnreachable` on each `get_state`, and each command on those sessions is refused by that code with the fix in the message. Nothing is signalled. `stop` still works, because it signals the recorded process identity and never needs a route, so the fix is `pi-agents stop <full-session-id> --revision <n> --yes` and then reopening the session. Refusing the start instead would have been loud and useless: it takes every other session on the root down with the one worker that cannot be reached.

**4. The daemon exits when the last client disconnects. Done.** On demand is the default: 30 seconds with nothing to do and the daemon exits, `PI_AGENTS_IDLE_EXIT_MS` or `--idle-exit-ms` selects another window, and `0` keeps it resident and now has to be asked for. A window that cannot be read refuses the start instead of staying up forever on it. `idleHold` in `runtime/daemon.mjs` names the one reason a daemon may not exit — a scheduled worker replacement, a launch, a command a worker still owes a reply to, or a connected dashboard — and only `frontend` connections count as clients, because a worker holds a connection too. Live workers deliberately hold nothing open, which is Claude Code's answer as well: the worker is Pi's parent, keeps its tail and its replay log, Pi keeps writing its own session file, and the next command starts a daemon that adopts all of it.

This one added lines rather than removing them, and the estimate that called it small was right about size and wrong about direction: 69 production lines added and 17 removed, net 52 across `runtime/idle-exit.mjs` and `runtime/daemon.mjs`, with 419 test lines added. Nothing was deleted because nothing existed to delete — the resident daemon was not a subsystem, it was a default of `0`. What the change removes is a class of state, not code: no process now outlives the work it was started for, so no dashboard connects to a daemon running a build that is no longer on disk.

Not adopted, deliberately: their PTY hosting and terminal-byte rendering. `docs/tmux-prototype-report.md` records why — killing the host kills every hosted session, terminal writes cannot prove Pi accepted text, and structured Stop and honest row state are both lost.

## Cleanup queue, from four read-only reviews

Ordered by concepts removed, not lines. Every item was verified against the code by the review that proposed it; where a review argued against a change, that verdict is recorded too.

**Delete `runtime/control-server.mjs`, 148 lines. Done.** A second socket-server implementation whose only consumer is its own test; production uses the private one inside `daemon.mjs`. Port its malformed-frame and socket-mode coverage to the surviving server first, then delete. Verified by search.

**Split transport out of `runtime/daemon.mjs` into `runtime/daemon-server.mjs`.** Socket lifecycle, authentication, role selection, the frontend protocol gate, JSONL framing, per-socket ordering, worker reply correlation, subscription lifetimes, bounded queues, shutdown draining. About 250 lines move out of a 1,549-line file that every commit in this release had to touch, which made it the serialization point for all parallel work. Do not split the rest of the request handler into one file per operation: its first half is a dispatch table, but its second half is a transaction coordinator and distributing that would add imports without removing concepts.

**Split `runtime/reconciliation.mjs`, 887 lines**, which currently holds three unrelated things: the worker router, the viewer subsystem, and the startup repair procedure.

**Collapse the frontend's three daemon API layers into one. Done.** `createDaemonDashboardBackend` and `createDaemonViewerClient` are gone; `createDaemonClient` in `app/daemon-client.mjs` owns every operation the list and the viewer send, and both controllers hold the same object. A reader no longer has to know which of two adapters reshaped an envelope, and the divergence between them is not expressible: a refusal is one typed failure on every operation, including `launch`, which used to answer with `{kind: "rejected"}` while the dashboard also matched a `{kind: "error"}` shape nothing returned. The viewer's five `typeof client.x !== "function"` capability guards went with the second shape, as did the `client.request(operation, payload)` calling convention no client had. Measured across three commits, `git show` over `git ls-tree` excluding `*.test.mjs`, `test/` and `perf/`: the tree goes from 16,936 production lines to 16,868, **net 68 removed** (264 removed against 196 added), with 50 test lines removed. The line reduction is the small half, as the review said: `app/daemon-client.mjs` grows by 147 lines because the operations moved into it, while `dashboard.mjs` loses 114 and `standalone-list.mjs` loses 88.

**Consolidate `app/list/` around three responsibilities.** Query projection, display-state derivation, row virtualization and responsive layout are four files that one interaction crosses; merging them into a session table is mostly movement, but reading one keystroke stops being a tour.

**Delegate more of the list to public Pi and pi-tui exports.** The viewer already uses Pi's `CustomEditor` and gets wrapping and history free; the list hand-rolls an append-only composer because pi-tui's `Editor` claims Ctrl chords the list needs. Generic overlays and autocomplete are still candidates. Package-root exports only.

**Reorganize the CLI around one client. Done.** One client did serve both front ends, on the `reconnect: false` flag `app/daemon-client.mjs` already had for the dashboard's own transaction client; no new mode flag was needed. What the CLI kept is what is genuinely its own: argument parsing, exit codes, the JSON output shape, the client identity file, a bounded deadline it reports rather than reconnecting past, and the ambiguity classification that decides whether a lost answer to a destructive command may already have run. `probeDaemon` keeps sending no request, which is how a client from this release still finds and stops a daemon from an earlier one.

Measured across two commits: 124 production lines added against 212 removed, **net 88 production lines**, with 5 test lines removed. `cli/session-commands.mjs` went 684 to 624 and `cli/daemon-commands.mjs` 365 to 337. Three quarters of it was one deletion: 92 lines of a second socket client that connected, authenticated, correlated one reply and classified its own transport failures, against the same socket with the same envelopes as the shared one. Two option names went with it, because the distinction they drew no longer exists: every CLI request now runs on a connection the command holds, so `heldConnectionRequest` is just `request` and the `heldConnection` flag that decided whether a lost socket was ambiguous is always true. `probeDaemon` and the refusal diagnosis stopped writing the same token-only handshake twice.

Two behaviours moved onto the shared client's rules. A read whose connection dies after submission is `CONNECTION_CLOSED` rather than `DELIVERY_UNKNOWN`, because nothing was mutated; the read-only timeout already said this and the socket-loss path contradicted it. The CLI's second, stricter response protocol is gone — `DUPLICATE_DAEMON_RESPONSE`, `TRAILING_DAEMON_DATA`, `UNEXPECTED_DAEMON_FRAME` and its own strict authentication check on the request path were four codes no other client minted. What survives is the rule in `docs/architecture.md`: an unparseable answer rejects the one request that owns it, and a destructive request whose answer cannot be read is `DELIVERY_UNKNOWN`. The strict authentication validation stays where it is load-bearing, in the diagnosis that names an earlier release.

**Contracts stay as they are.** A review costed replacing 422 hand-written lines with a declarative table and concluded the win is not real: these validators run on every frame across a process boundary, and their messages name the exact offending field, which was load-bearing while debugging this release. 422 lines is what strictness costs.

**Consolidate duplicated test layers.** Controller-level repetitions of behavior already owned by focused units; four candidates measured at 45 to 150 lines each. Keep the real-process suites that catch what a unit test cannot, and say which failure each one catches.

**Close the remaining doubles that cannot fail the way production fails.** Three defects shipped behind a fully green suite because a fake only modelled success: a fake `request` hid a broken `daemon stop --stop-workers`, a fake server that accepted every viewer subscription hid a frozen viewer, and a fixture Pi emitting a help banner reinforced the bug it should have caught. The remaining sites are listed in the test review. This is per-site work and it costs real-process time, so it is a judgment call rather than a sweep.

**`runtime/daemon.integration.test.mjs` is nearly 2,000 lines** and tests every extracted concern through one seam, which reinforces `daemon.mjs` as the only place a change can land. Split it alongside the production split, not before.
